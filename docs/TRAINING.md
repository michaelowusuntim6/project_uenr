# Training

All training is plain C, one process, no framework. The default pipeline is
strictly sequential:

```
pretrain -> SFT -> DPO -> GRPO -> eval
```

Each phase loads the previous phase's checkpoint. The loop lives in
`src/train/train.c` (pretrain/SFT) and `src/train/align.c` (DPO/GRPO).
LoRA, PPO and the learned reward model remain in the tree as legacy
experiments/tests but are no longer part of the CLI pipeline.

## Quickstart

```bash
make -j2
./uenr tok-train          # ~ seconds; writes artifacts/
./uenr prepare            # streams 200 MiB -> UDAT + SFT/pairs
./uenr train --steps 100  # pretrain
./uenr sft   --steps 50 --load checkpoints/model.bin
./uenr dpo   --steps 20 --load checkpoints/sft.bin --ref checkpoints/model.bin
./uenr grpo  --steps 20 --load checkpoints/dpo.bin --ref checkpoints/model.bin
./uenr eval  --load checkpoints/grpo.bin
```

For the whole chain use:

```bash
scripts/train_pipeline.sh --short     # 4/4/2/2 local verification
scripts/train_pipeline.sh --steps 20  # 20 steps per phase
```

Or run `./uenr-menu` and choose **8. Run training pipeline**.

## Pretraining

- Data: `data/train.bin`, a `UDAT` file (magic, version, uint64 count, vocab,
  dtype, then uint16 ids). `val.bin` is held out by `prepare.val_percent`.
- Each optimizer step processes `grad_accum` micro-batches of
  `micro_batch = batch_size / grad_accum` sequences each.
- For each micro-batch: forward, fused softmax+CE, scale `dlogits` by
  `1/(grad_accum · supervised_tokens)`, backward. Gradients accumulate over
  the whole step.
- Global L2 norm is computed, clipped to `training.clip`, then AdamW updates
  every non-norm tensor. Norm gains use zero weight decay.
- The step budget comes from the epoch formula in `docs/FORMULAS.md` §12.

Observed on the target laptop (default config, 2 threads): ~870 tokens/s,
~8.8 GFLOP/s end-to-end, ~13% of the measured 2-core roof. A 100-step run
moved the loss from 7.52 to 6.61 (EMA 7.04); the first 20 steps were still
inside warmup, so most of the movement comes as the LR reaches 5e-4.

## SFT

- Data: `data/sft.jsonl`; `uenr_sft_load` builds chat-templated ids and
  autoregressive next-token labels.
- Labels are **shifted**: `label[t] = ids[t+1]` when the next token was
  generated by the assistant (assistant content or the `<end>` closing an
  assistant turn). The assistant role marker, user/system/tool text and the
  final token carry `tokenizer.ignore_index`. Thus a token is never trained
  to reproduce itself; the assistant role marker supplies the context for
  predicting the first assistant token.
- `training.sft_pack` (default true) packs several conversations into each
  sequence row and marks each document start; attention is block-diagonal, so
  documents never attend to each other. Remaining padding carries `pad_id`
  and `ignore_index`, so it never contributes to the loss. A short local A/B
  measured 733 vs 643 tok/s (1.14x) at seq 128.
- The optimizer is the same; the model is initialized from
  `paths.model_out` (pretrained) when it exists.

## Retired from the default pipeline

LoRA/QLoRA (`uenr lora`), PPO (`uenr ppo`) and the learned reward model
(`uenr train-rm`) are not exposed by the CLI or the menu anymore. Their
low-level implementations and regression tests remain for research, but the
supported pipeline is the four-phase sequence above: full fine-tuning on an
8.45M model does not need adapters, GRPO replaces sequence-level PPO, and
rule/verifier rewards replace the synthetic reward model.

## DPO

`uenr dpo` loads preference pairs and a frozen reference
(`dpo.ref_checkpoint`, falling back to `model_out` and failing closed if
neither is a valid checkpoint). For each pair it builds
`chat(prompt) + completion + <end>` for chosen and rejected, computes sequence
log-probs under policy and reference, and applies the DPO loss and gradient in
`docs/FORMULAS.md` §14. Only the policy is updated.

With `δ = (log π(w) − log ref(w)) − (log π(l) − log ref(l))` and
`z = βδ`:

```
L  = −log σ(z)
∂L/∂log π(w) = −β σ(−z)      ∂L/∂log π(l) = +β σ(−z)
```

Both coefficients are computed by `uenr_dpo_loss`/`uenr_dpo_logp_grad` and
regression-tested against finite differences (`tests/test_align.c`). A descent
step therefore raises the chosen log-probability and lowers the rejected one,
increasing `δ`.

## GRPO

`uenr grpo` samples completions from the current policy for a prompt, scores
them with the configurable heuristic reward in `[rl]`, and updates with
sequence-level policy gradients. It loads the DPO checkpoint by default and
uses the frozen pretrained checkpoint as reference:

Let `r = exp(log π_θ(y) − log π_old(y))` be the sequence-level ratio and
`A` the advantage (reward minus the group mean, normalized by the group
standard deviation for GRPO).

- **GRPO**: `L = −A·log π_θ(y) + kl_coef·KL`, so the log-probability
  coefficient is `−A + kl_coef`. Positive relative advantage raises the
  sequence probability; negative lowers it.
- **KL**: both use the frozen reference and the single-sample k1 estimator
  `KL ≈ log π_θ(y) − log π_ref(y)`. The reference term is constant, so its
  gradient with respect to the policy log-probability is `+kl_coef`; the
  penalty pulls the policy back toward the reference.
- `rl.temperature` scales the rollout sampling distribution only. Policy
  log-probabilities are evaluated at `T=1` for a consistent objective.

R1-style additions: `rl.reward_verify` adds an exact-answer arithmetic
verifier on top of the heuristic reward, a group whose reward standard
deviation is below 1e-4 is skipped instead of applying a zero advantage, and
`grpo.ref_refresh` (default 400, 0 disables) copies the policy into the
reference periodically. There is deliberately no learned value head, no
entropy bonus and no GAE (`gamma`/`lambda`); `grpo.group_size`,
`grpo.kl_coef` and `grpo.ref_refresh` are the supported controls. The group baseline is R1's GRPO recipe. Mathematical helpers are
regression-tested in `tests/test_align.c`; the legacy PPO surrogate test
remains but PPO is not in the pipeline.

## Checkpoints and resume

- Every `run.checkpoint_every` steps (default 500): `checkpoints/step_XXXXXX.bin`
  with parameters and the active optimizer state. The newest three are kept.
- Final: `paths.model_out` (pretrain), `sft_out`, `dpo_out`, `grpo_out`.
- `SIGINT`/`SIGTERM` stops after the current step and writes `model_out`.
- `run.resume = true` (or `--resume`) discovers checkpoints independently of
  the final output file: periodic step files are considered even when
  `model_out` does not exist (for example after a crashed first run). Files
  are ranked by the step stored in their **header**, not by filename; corrupt
  or wrong-magic files are skipped. If the newest cannot be loaded, the
  configured init/output checkpoint is tried, then the run starts fresh with a
  clear warning.
- Optimizer state is restored for Adafactor, AdamW, INT8 Adam and Muon; the
  checkpoint kind is stored in the header. A resume with a different optimizer
  configuration fails with `UENR_ERR_SHAPE` before weights are modified rather
  than silently continuing with cold moments. Initialization after a load is
  idempotent, so the trainer cannot overwrite restored moments.
- Writes are atomic (`.tmp` + `rename`).
- Format v2: `UMDL` magic, version, model dims, step, optimizer kind, parameter
  count, extra-byte count, then the aligned parameter block and optional
  optimizer payload.

## Low-RAM training modes

| Mode | Peak RSS (seq 512, 5 steps) | Speed | Notes |
|---|---|---|---|
| Default (Adafactor, full activations) | 382 MB | 1.00× | Includes the 106 MB mmap corpus. |
| `block_checkpoint = true` | 248 MB (1.54× less) | 0.81× | One layer's activations; layer forward re-run in backward. |
| `block_checkpoint + fp16_activations` | 236 MB (1.62× less) | 0.78× | FP16 probability storage; loss identical to 4 dp. |

The legacy LoRA/QLoRA path used a gradient sink and no base optimizer state;
it remains available in code for research but is not part of the supported
pipeline. See `docs/CHECK_LIST02.md` for its measurements.

## Logging

Every `run.log_every` steps the trainer prints and appends to
`checkpoints/train.csv`:

```
step, lr, loss, ema, tokens_per_s, flops_per_s, mfu_pct
```

FLOPs use `6·(active_params + V·C)` per token (forward + backward, tied head).
MFU is relative to the measured `33.9 GFLOP/s × threads` roof.

## Gradient-checked invariants

`tests/test_gradcheck.c` finite-differences every parameter family on dense and
single-expert models, including RMSNorm, RoPE, GQA attention, SwiGLU,
tied-head logits, and the shared/routed experts. Top-1 routing is piecewise
constant, so router gradients are derived analytically and the numerical check
uses smooth configurations.
